# Curmerce 基础验收清单

这份清单只验证单体应用、本地 MySQL/Redis、数据库事务和本地定时任务。它不验证 Redis/Lua、消息队列、WebSocket、分布式事务或微服务拓扑。

## 1. 环境与登录

- [ ] MySQL 在 `127.0.0.1:13306` 监听，Redis 在 `127.0.0.1:16379` 监听。
- [ ] 后端和前端使用同一组 API 地址启动。
- [ ] 管理员可以登录后台，普通用户可以登录商城端。
- [ ] 未登录访问商品、社区、限时发售和拍卖列表/详情可以读取公开数据。
- [ ] 未登录创建订单、购买限时发售、出价、结算、评论和互动会被拒绝。

## 2. 普通商品订单

- [ ] 管理员创建或审核商家，商家创建店铺和商品。
- [ ] 商品提交审核、审核通过、上架后出现在商城目录。
- [ ] 用户维护收货地址，将一件商品加入购物车并创建订单。
- [ ] 创建订单后 SKU 库存减少，订单保存商品和收货地址快照。
- [ ] 相同用户重复提交相同幂等键只返回原订单，不重复扣库存。
- [ ] 库存不足、空购物车、其他用户地址和跨店购物均被拒绝。
- [ ] 模拟支付成功后订单变为“已支付待发货”。重复支付回调不重复推进状态。
- [ ] 商家只能看到自己的待发货订单；发货需要物流公司和物流单号。
- [ ] 重复发货、操作其他商家订单、对有活动退款的订单发货均被拒绝。
- [ ] 买家确认收货后订单变为“已完成”；未发货或其他用户订单不能确认。
- [ ] 待支付订单取消或超时后恢复 SKU 库存，已支付订单不能直接取消。
- [ ] 退款申请、审核、模拟退款回调和重复回调状态符合预期。

## 3. 限时发售

- [ ] 商家只能为自己店铺的商品创建活动，并设置有效时间、活动价和每人限购数。
- [ ] 活动未开始、已结束、库存不足、重复购买和超出限购均被拒绝。
- [ ] 购买成功同时创建普通待支付订单，活动库存和 SKU 库存都被预留。
- [ ] 支付成功后限时发售购买记录变为已支付。
- [ ] 取消订单或支付超时同时恢复活动库存和 SKU 库存。
- [ ] `CommerceEventLifecycleJob` 推进“待开始 -> 进行中 -> 已结束”。

## 4. 基础拍卖

- [ ] 商家只能为自己店铺且有库存的 SKU 创建拍卖。
- [ ] 未开始、已结束、卖家本人出价、低于起拍价/最小加价和重复幂等键均被拒绝或幂等返回。
- [ ] 结束拍卖后最高价出价人成为胜者；无人出价时不产生胜者。
- [ ] 只有胜者可以结算，结算只创建一个普通待支付订单。
- [ ] 拍卖胜者订单可以走普通支付、发货、确认收货和退款路径。
- [ ] 胜者订单支付超时会释放 SKU 库存；当前基础版本不会自动转让给下一位竞拍者。

## 5. 社区到商品

- [ ] 用户创建帖子草稿并保存图片、话题和商品编号。
- [ ] 关联不存在或当前不可见商品时，帖子创建/修改被拒绝且不产生半成品关系记录。
- [ ] 帖子详情展示关联商品卡片，商品卡片可以进入商品详情页。
- [ ] 商品下架后，社区详情不再展示该商品卡片，但帖子正文仍可查看。
- [ ] 帖子、评论、点赞、收藏、关注和举报的权限及幂等行为符合预期。

## 6. 记录结果

每次验收记录：执行时间、账号角色、订单/活动/帖子 ID、预期结果、实际结果和失败日志。不要把密码、Token 或数据库凭据写入仓库。
